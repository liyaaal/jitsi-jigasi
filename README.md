# Meeting Pro

Локальная запись встреч из браузера и приложений, расшифровка и протокол через OpenAI или Groq. **Для расширения не нужен сервер Jitsi, Node.js или API-ключ на этапе записи.**

## Быстрый старт — Chrome / Edge

1. Скачайте проект и распакуйте его.
2. Откройте `chrome://extensions` (в Edge — `edge://extensions`).
3. Включите **Режим разработчика → Загрузить распакованное расширение** и выберите папку `jitsi-ai-extension`.
4. Нажмите значок Meeting Pro. Откроется отдельная вкладка управления.
5. Выберите источник, проверьте индикаторы звука, предупредите участников и нажмите **Начать запись**.
6. После **Остановить** аудио доступно в истории. Для текста введите свой API-ключ выбранного провайдера и нажмите **Расшифровать и создать протокол**.

Название папки `jitsi-ai-extension` сохранено для совместимости с прежней установкой. Теперь расширение записывает звук независимо от сервиса встречи.

## Что можно записать

| Источник | Как выбрать | Ограничения |
|---|---|---|
| Google Meet, Jitsi, Zoom Web, Teams Web, Discord Web и другие сайты | «Вкладка браузера», выбрать вкладку со встречей и включить передачу её аудио | Записывается звук выбранной вкладки. Доступность звука проверяется до записи. |
| Zoom, Teams, Discord, Telegram и другие приложения | «Приложения / весь экран», выбрать экран и включить системный звук | В Chrome/Edge на Windows зависит от доступных опций браузера. Может захватываться весь звук компьютера, включая уведомления. Это не отдельная интеграция с каждым приложением. |
| Очная встреча / голосовая заметка | «Только микрофон» | Записывается выбранный в браузере микрофон. |

На macOS/Linux захват системного аудио зависит от ОС и браузера. Если в окне выбора нет передачи системного звука, используйте веб-версию сервиса и захват вкладки. Расширение обнаруживает отсутствие аудиодорожки и не разрешает пустую запись. Наличие дорожки само по себе не гарантирует слышимую речь: проверьте индикатор на реальном разговоре.

**Микрофон и звук встречи сохраняются раздельно.** Имена отдельных собеседников в общем аудио автоматически не определяются. Это не диаризация. Используйте наушники, чтобы избежать эха. Кнопка mute в Zoom/Meet не отключает микрофон, отдельно подключённый к расширению.

## Сохранение и приватность

- Аудио сохраняется в IndexedDB расширения на этом устройстве. Оно не отправляется в облако до нажатия кнопки расшифровки.
- Запись состоит из самостоятельных WebM/Opus-файлов примерно по минуте. Каждый файл можно скачать и воспроизвести отдельно. Между отрезками возможен небольшой разрыв при перезапуске MediaRecorder.
- При штатной остановке сохраняется последний отрезок. При аварийном закрытии браузера или вкладки могут потеряться последние 60 секунд; завершённые отрезки остаются в истории.
- Оставляйте вкладку Meeting Pro открытой во время записи и обработки. Не допускайте сна компьютера. Интервалы браузера могут замедляться в фоне; жёсткий лимит длины отрезка не гарантируется.
- Перезагрузка вкладки восстанавливает историю. Удаление расширения/данных браузера удаляет записи. Скачайте важное заранее.
- Ключ хранится в `chrome.storage.session` до конца сессии браузера, не в исходниках и не в хранилище сайта встречи. Старый ключ прежней версии удаляется из `storage.local` при первом запуске.
- После выбора AI аудиофайлы отправляются этому провайдеру; распознанный текст отправляется для протокола. Услуги API могут быть платными.
- Ошибки API показываются в отчёте. Успешные расшифровки отрезков сохраняются, повторная попытка обрабатывает недостающие. Оригинальный транскрипт не переписывается моделью «для красоты».
- Начало аудиоотрезка в тексте — приблизительная временная отметка, не точное время каждой реплики. Решения AI нужно сверять с оригиналом.

## API

| Провайдер | API Base URL | Аудио | Протокол |
|---|---|---|---|
| OpenAI | `https://api.openai.com/v1` | `whisper-1` | `gpt-4o-mini` |
| Groq | `https://api.groq.com/openai/v1` | `whisper-large-v3-turbo` | `llama-3.3-70b-versatile` |

Ключ должен принадлежать выбранному провайдеру. Произвольные API URL не принимаются, чтобы не отправить ключ на ошибочный адрес. Лимит одного аудиофайла в приложении — 24 МиБ. Полный транскрипт длиннее 100 000 символов сохраняется без общего AI-протокола. Автоматических повторов платных запросов нет.

## Отдельный бот для Jitsi

Бот по-прежнему предназначен только для Jitsi. Он входит отдельным участником `Meeting-Pro-Recorder`, записывает доступные удалённые аудиодорожки и сохраняет отдельную сессию на каждый запуск. Для других сервисов используйте расширение.

Нужны Node.js 22+ и Chromium Playwright:

```bash
npm ci
npx playwright install chromium
cp .env.example .env
# Заполните .env своим ключом или установите RECORD_ONLY=true
npm start -- "https://your-jitsi.example/Room"
```

На Linux установку системных зависимостей Chromium можно выполнить через `npx playwright install --with-deps chromium`. В PowerShell вместо `cp` можно использовать `Copy-Item`.

Настройки `.env`: `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `TRANSCRIPTION_MODEL`, `SUMMARY_MODEL`, `TRANSCRIPTION_LANGUAGE`, `RECORD_DURATION_MS` (по умолчанию 30 минут, максимум 24 часа), `HEADLESS`, `RECORD_ONLY`. Для лобби/входа используйте `HEADLESS=false` и вручную разрешите вход. Ожидание подключения — до 120 секунд; бот не обходит авторизацию.

`Ctrl+C` во время записи завершает текущие аудиофайлы, затем запускает обработку, если `RECORD_ONLY` не включён. Сессии лежат в `recordings/<дата-id>/`: `session.json`, аудио, `transcript.json`, `transcript.txt`, `summary.md`.

Повторная обработка сохранённой сессии:

```bash
npm run transcribe -- "recordings/<дата-id>"
```

Записи старого формата (`recordings/<participant>/audio.webm` без `session.json`) автоматически не импортируются. Сохраните их отдельно перед обновлением. Бот использует внутренние объекты Jitsi и DOM аудио; при изменении версии Jitsi совместимость нужно перепроверять.

## Проверки

```bash
npm test
npm run test:browser
```

Unit-тесты проверяют выбор провайдера, ошибочные ответы, ограничения, восстановление расшифровки и проверку входных данных. Браузерные тесты запускают настоящее расширение Chromium с синтетическими аудиопотоками: самостоятельные WebM, финальный отрезок, историю после перезагрузки, сбой AI, повторную обработку, экспорт, удаление, отсутствие аудио и мобильную ширину. В CI используются эти же проверки.

Они **не заменяют** проверку реального звонка, выбора системного звука в конкретной ОС, действующего платного API и серверного развёртывания.

## Серверные субтитры

Если нужен собственный Jitsi с локальными live-субтитрами, используйте соседний проект [jitsi-jigasi-setup](https://github.com/liyaaal/jitsi-jigasi-setup). Это отдельный сценарий: Jitsi + Jigasi + Vosk на сервере. Расширение работает без него.

Документация: [Chrome: захват экрана и звука](https://developer.chrome.com/docs/web-platform/screen-sharing-controls), [Chrome: storage](https://developer.chrome.com/docs/extensions/reference/api/storage), [Groq: speech-to-text](https://console.groq.com/docs/speech-to-text).
